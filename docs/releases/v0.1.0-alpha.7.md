## Notes (the release body)

**`neuralos-snn` 0.1.0-alpha.7** — the `no_std`, i16 fixed-point
spiking-neuron library for RISC-V edge silicon.

Since alpha.6:

- **Both divisions by 1000 in `integrate_and_fire` narrow to `i32`
  when the value fits:** the same truncating division, a multiply-high
  by the constant on a 32-bit core instead of a software 64-bit
  division; a value that does not fit takes the `i64` division as
  before. Exact by construction, pinned by new property and boundary
  tests; the two `i128` exactness proofs are unchanged.
- **`dt_over_tau` computes in `u32` when `dt * 1000` fits**, one
  hardware divide; the `u64` formula above it.
- **The spike ring masks its store indices**, the same slots with a
  bound the optimizer can see.
- **`#[inline]` on `integrate_and_fire`.** No public API moved.

**Measured on the ESP32-C3 (rv32imc, 160 MHz), same SuperMini and
same firmware source as alpha.6's measurement:** the neuron as a
network holds it (in memory, dt at run time) costs **1,579 ns per
step, against 3,878 on alpha.6**, and the burst the compiler can see
through costs 563, against 2,863. Every behavior figure is identical
(147 spikes in the 10,000-step burst, the first at step 55, the same
checksum of the spike steps), and no 64-bit software division is left
in the step. The 2,842 ns of the alpha.6 release was the second
burst's shape; a network's run-time dt cost more on alpha.6, 3,878.
Mechanism, listings and pins: `evidence/esp32c3-bringup/README.md`
§ Third entry.

**On x86-64** the host spike-path bench is about 2 to 2.5 ns per step
slower (+22 to 26 %), bisected across the round's commits and
recorded, not fixed: the chip is the target.
`evidence/esp32c3-bringup/README.md` § Host bench, round 27.

**The attached binary** is the firmware of that measurement, built at
the tagged commit by `firmware/esp32c3/build.sh` (no home path in it
by construction; sha in `SHA256SUMS` and the `.text` pin in the
evidence README). Rebuild from source by the evidence README § Rebuild
+ run; compare the `.text` section, not the file.

What this release is not: not a benchmark (one neuron, one board),
not a claim about the network layer on the chip, not a change to any
published number of the paper.
